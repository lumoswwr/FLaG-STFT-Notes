# 为什么选择 STSB、Sprint 和 IMDB 这三种文本任务？



## 1. 三种任务要求模型做什么？

| 数据集 | 模型要做的事 | 为什么适合用来比较池化方法 |
| --- | --- | --- |
| **STSBenchmark（STSB）** | 给两句话的语义相似程度打分 | 检查句向量是否能保留整体语义相似性 |
| **SprintDuplicateQuestions（Sprint）** | 判断两条问题是否表达相同或重复的提问意图 | 检查句向量能否区分相似但意图不同的问题 |
| **IMDB** | 判断电影评论是正面还是负面 | 检查模型对较长评论的情感分类能力 |

!!! note "关于 Sprint 的任务说明"
    **Sprint 是重复问题识别，不是“一个问题和一个答案是否匹配”。** 例如“如何给手机开机？”与“手机怎样启动？”可能是重复问题；“手机怎样调节音量？”则不一定与前者重复。这样的例子只是说明任务目标，并非引用数据集中的原始样本。

## 2. 最初的三个研究假设

### STSB：直接对 token 求平均，可能有利于整体语义相似度

Mean pooling 将有效 token 的向量平均。FFT 的零频率 DC 与 Mean 成正比，因此我们猜测 DC 对 STSB 可能很重要，而复杂的 FLaG 变换也可能改变原有的语义表示。

### Sprint：仅靠直接 Mean 的余弦相似度，可能不足以区分重复问题

两个问题可能共享许多词或讨论相近话题，却并不是同一个问题。我们最初推测频域变换也许可以提供额外的判别信息。


### IMDB：长评论可能需要与短句不同的信息汇总方式

IMDB 常包含比 STSB 更长的文本，需要汇总跨越多个 token 的情感信息。我们因此用它补充比较 Mean、FLaG 和融合方法是否有任务差异。

## 3. 后续实验实际观察到了什么？

- STSB 中直接 Mean 在部分匹配协议下优于原始 FLaG；[Alignment-aware](mean-compatible-flag.md) 将 Mean 显式引入后改善了相似度结果。
- Sprint 中，原始直接 Mean + cosine 的 AP 较低；而 [只保留 DC](dc-frequency.md) 训练的 FLaG 能获得更高的 AP，说明 DC 中的任务信息能否被利用与后续模型有关。
- IMDB 的五种子实验里，Mean、FLaG 和 Alignment-aware Accuracy 接近，分别约为 0.9525、0.9521、0.9526。

这三种任务帮助我们区分：**句向量本身包含什么信息**，以及**后续使用什么方式把这些信息变成预测**，是两个不同问题。
